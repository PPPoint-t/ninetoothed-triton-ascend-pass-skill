# 编排、证据和恢复契约

采用单主控 agent + 显式持久状态机 + 确定性子进程 + 回归门禁。主控负责迁移语义，脚本执行固定边界动作。首版不需要后台服务或模型凭据，也不会退出会话后自启动 agent。

## 状态转换

```text
初始化/恢复 -> 选规则 -> 算子发现 -> 目标测试确认/最小测试迁移
  -> 修改前基线 -> 0.25/0.26 对照 -> 单个最小私有实现
  -> 同一算子回归 -> 非目标核心回归 -> 比较 -> 完成/下一条
阶段结束 -> 清单完整算子回归 -> 中文阶段报告
普通失败 -> 保留原记录 -> 有限修正（最多三种源码）
新增回归 -> 禁止完成
设备致命错误/结果未知 -> 熔断 -> 外部恢复 -> 健康检查 -> 新执行
```

算子发现必须先检查目标 `tests/` 是否已有语义覆盖。有覆盖就先运行原状基线；没有覆盖才允许从 ntops 迁移一个最小案例，并在记录中写来源和唯一缺口。`finish` 是规则门禁，要求当前源码的双 target 源码核心对照、Ascend 设备核心回归，以及相关目标算子在两层有可归因证据。0.26 已经支持的规则应以“无需迁移”完成，不得为了保留旧版本文件制造 patch。`compare` 只证明无新增回归；原有失败仍是失败，不等于全部通过。

## 真相与记录

- 配置、规则进度和每次执行的 `记录.md` 是主状态，中文表格格式版本为 1。
- 每次执行先落盘“执行中”，每结束一个案例原子更新；日志/观测/源代码在独立案例目录。总览可以随时从记录重建。
- 文件写入采用同目录临时文件、fsync、原子替换；主控锁保证本批次一个写入者。设备锁跨批次共用。
- `status` 是只读查询，不争用主控写锁，运行期间可以查看已经落盘的进度；恢复和状态推进仍必须取得写锁。
- 保留结构字段与表头；自由文字可以加在结构表格之后。重复字段、缺字段、格式未知必须报错，不能由模型猜状态。
- 源/规范变化、目标 HEAD 变化需新批次。目标源码变化使旧结果失效；测试/清单变化需重新 collect，条件变化后的前后比较需新基线。
- 每次运行记录版本、相关环境、输入规格、实际 artifact/source/pass trace、命令和退出状态。清单完整集不是目标仓库所有 tests。

## 子进程与设备

一例一进程、shell=False、独立进程组、单例时限与批次预算。超时先终止后杀死本流程拥有的进程组；不杀其他作业。pytest 插件自动加载关闭，项目 addopts 清空，避免外部插件和 quiet 累加影响执行。

TERM 与 KILL 后分别最多等待两秒，避免遇到不可中断内核等待时主控永久卡住。若进程仍存活，保留 PID 和 `/proc` 启动标识；即使显式请求恢复，也必须先确认该原进程已消失。遗留进程还会持有继承锁，主控退出不代表设备通道已释放。

仅使用清单中的精确函数入口，真实路径必须落在目标 tests/。插件对真实 `Compiler.compile` 和 `Handle.__call__` 插桩，不修改生产文件；检查 ninetoothed 导入路径、artifact backend、schedule trace、实际 NPU 输入和同步。纯源码阶段意外执行 kernel 会失败。

设备队列默认选择物理卡 0，子进程通过 `ASCEND_RT_VISIBLE_DEVICES` 映射为逻辑 npu:0；`--device` 选择其他物理卡，锁按物理编号隔离。每次设备执行先用 torch 小运算与 active Ascend driver 检查设备健康，不计入算子通过数。原有可见设备环境记录在快照，执行时的物理映射单列。

timeout、507014、进程 signal 或健康检查失败会使本工作流的设备状态隔离，余下节点阻塞。锁只协调遵守协议的流程，不能防止外部用户占卡；运行前确认可独占使用，绝不自动结束外部工作负载。

## 恢复

`recover` 识别遗留执行中状态并标为中断待核对，不自动重放。NPU 遗留执行会隔离设备。即使子进程已结束，AICore 也可能未恢复。

确认外部恢复后执行 `recover-device --after-external-recovery`；它只重新做有限健康检查。它不 reset 设备，不清缓存，也不能证明旧 kernel 的真正根因已经修复。

外部 kernel 提交与 Markdown 写入不能构成同一事务，因此不承诺“恰好执行一次”。结果未知时不能靠自动重试猜成功。不同源码验证最多三次，普通失败不自动吞掉；偶发失败仍保留。

## 回归与证据限制

实际执行中源码/环境变化会使记录不可用于比较。每节点前后对照：保持通过、本轮修复、原有失败、新增回归或验证缺失。每个迁移变体单独记录，至少保留删除旧改动的 baseline 和每个单步变换的执行结果；错误原因变化、节点缺失、原通过变 skip 都是回归或验证缺失。

规则完成门禁还核对同一源码与当前规则的历史相关执行：不能跳过先前新增失败，只提交随后重跑成功的比较文件。真正源码修复产生的新版本允许重新验证；旧失败证据保留。

部分通过的算子必须按失败路径归因，不能用“整个算子失败”或“旧 pass 已存在”替代分析。记录应包含当前 0.26 SSA/pass trace、失败的 shape/dtype/layout/控制流、0.25 对应规则、当前只迁移的一个变换、非目标回归结果，以及为什么停止在该最小范围。

源码生成不等于 toolchain build；当前算子 runtime 将 lazy build 与 launch 同进程执行，没有独立 build-only 就明确未独立验证。没有 NVIDIA 硬件不声称 NVIDIA runtime 回归通过。

环境摘要记录安装版本、Triton 关键文件和可发现的 CANN 版本文件，属于证据身份，不是新的编译缓存实现。不能自动覆盖所有未知安装布局；更换编译器后新批次，并按用户既定流程清理相关缓存、重启。无需修改公共 cache 指纹。
